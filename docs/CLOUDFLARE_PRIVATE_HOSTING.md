# نقل استضافة شركة الزيادي إلى Cloudflare Pages (تجهيز أولي)

## الوضع الحالي
- التطبيق موقع ثابت HTML/JS مع manifest.json و sw.js، ويمكن نشره على Cloudflare Pages دون بناء Flutter أو خادم جديد.
- **لا تغيّر خصوصية المستودع أو تعطل GitHub Pages قبل التحقق من الرابط الجديد.**
- عند الانتقال إلى نطاق جديد تتغير مساحة localStorage وCache؛ على الموظفين تسجيل الدخول مجددًا، ويجب مراجعة أي بيانات محلية غير متزامنة قبل الانتقال.
- فحص auth-guard.js أظهر أنه يعتمد على token وrole في localStorage. هذه ليست آلية تفويض آمنة لقاعدة البيانات؛ يجب التحقق من صلاحيات القراءة والكتابة في قواعد الخادم قبل اعتماد الانتقال.

## خطوات نشر Cloudflare Pages
1. Cloudflare Dashboard → Workers & Pages → Create → Pages → Connect to Git.
2. اختر المستودع a7medelzaiady-hub/ahmed، الفرع main **بعد دمج PR الاختبار**.
3. Framework preset: None؛ Build command: اتركه فارغًا؛ Build output directory: `.` (جذر المستودع).
4. انشر واحصل على عنوان `*.pages.dev`، ولا تنقل أي مفاتيح خاصة إلى ملفات JavaScript.
5. اختبر index.html وmanifest.json وsw.js والصفحات الداخلية، وتحقق من أن كل المسارات تعمل تحت أصل النطاق الجديد.
6. افحص Authorized Domains لمزود تسجيل الدخول، وCORS وأي روابط أو قواعد تعتمد على النطاق القديم.
7. اختبر المبيعات والعملاء والجرد والرواتب والسلف والبيانات غير المتزامنة وتحديث service worker على جهاز حقيقي.
8. بعد النجاح جهّز APK داخليًا. الأفضل TWA إن كانت شروط PWA وDigital Asset Links مستوفاة؛ وإلا قيّم WebView آمنًا. يتطلب APK إعداد بيئة Android والتوقيع واختبارًا فعليًا.
9. **فقط بعد نجاح الرابط والـ APK وموافقة المالك** غيّر المستودع إلى Private.

## نقاط تحتاج إصلاح/تحقق قبل الإصدار
- `manifest.json` يشير إلى `icon-192.png` بينما `sw.js` يسرد `icon-192.jpg`: تحقق من وجود PNG الفعلي.
- `sw.js` يقوم بتخزين عدد كبير من صفحات النظام مسبقًا: راجع الملفات المفقودة وحدود التخزين والتحديثات وتجنب أن يفشل تثبيت العامل بالكامل بسبب ملف واحد.
- لا تضع أسرارًا في كود العميل؛ تغيير المستودع إلى Private لا يخفي JS الذي يحمّله المتصفح.
- قد يلزم تحديث روابط التنزيل/المشاركة والاختصارات المثبتة لدى الموظفين بعد تغيير النطاق.

هذه الوثيقة تحضيرية فقط؛ لم يتم نشر Cloudflare أو بناء APK أو اختبار البيئة الحقيقية بعد.
